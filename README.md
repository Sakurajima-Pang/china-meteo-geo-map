# 中国一级气象地理区划交互地图

一个**单文件、零依赖、完全离线**的中国交互式矢量地图。以 DataV.GeoAtlas 行政区划为底图，
叠加中国气象局的 11 个一级气象地理区划、100 座山脉、29 条河流与 17 个湖泊，支持悬停查询、
单击联动、区划框选、要素高亮、缩放平移，以及经纬网叠加、经纬度读数与图上测距。

成品：[`中国气象地理区划交互地图.html`](中国气象地理区划交互地图.html)（886.4 KB，
内嵌全部数据与样式，无任何外部资源引用，双击即可在浏览器中打开）。

> **定位声明**：本图是教学与演示用途的**示意图**，不作为权威地图或气象业务依据。
> 区划界线为近似范围，跨区省份的城市级归属属**推断性细化**。详见页面页脚的
> 「数据来源与制图说明」，以及文末的[已知局限](#已知局限与披露)。

## 效果与功能

| 功能 | 操作 |
|---|---|
| 省份信息 | 悬停省份高亮，单击在右侧展开区划归属与地理要素清单 |
| 区划框选 | 勾选右侧 11 个一级气象地理区划，对应范围着色 |
| 要素高亮 | 勾选山脉 / 河流 / 湖泊，在地图上高亮并显示注记 |
| 市界显示 | 「显示全国市界」叠加全国 475 个地级（区级）单元界线 |
| 视图操作 | 滚轮缩放、拖拽平移、双击复位 |
| **经纬网** | 「显示经纬网」叠加 5° 间隔的经纬格线与度标；整十度线加粗，可随时关闭 |
| **经纬度显示** | 「显示经纬度」开启后，左上角实时读出指针位置（WGS-84 表述） |
| **测距** | 「测距」进入后连续单击取点，显示各段与总距离；Esc 退出、Backspace 删末点、双击结束 |
| 键盘可达 | 省份路径可 Tab 聚焦，Enter / Space 选中 |

地图由两个部分构成：主图（73–135.5°E / 17.6–53.8°N，墨卡托投影）与
**南海诸岛附图**（104.5–125°E / 2.5–24.5°N，含九段线与 6 个岛礁符号）。
主图按「外环最大纬度 < 17.8°N 剔除」的规则排除南海岛礁，使其只在附图中呈现。

### 关于经纬度读数与测距的精度

这两项功能都建立在**逆墨卡托投影**之上（屏幕坐标 → 经纬度），距离用
**球面大圆（Haversine）公式**按地球平均半径 6371.0088 km 计算 ——
主图横跨约 62 个经度，平面欧氏距离在此尺度下误差显著（喀什→上海：
大圆 4180 km vs 平面近似 4229 km），故未采用。

需要注意两点，均已在页脚披露：

1. 读出的是**画面投影坐标反算、按 WGS-84 表述**的数值；底图本身为 GCJ-02，
   两者存在约 300–600 m 的系统性偏移。
2. 测点由屏幕坐标反算，精度受画面比例限制（主图约 21 像素/经度 ≈ 5 km/像素）。

因此两个功能**仅用于数量级估算**，不可作为测绘或业务量算依据。

### 关于经纬网

经纬网按 **5° 间隔**绘制（`GRID_STEP = 5`），这个取值是权衡的结果：
主图在中性视图下横跨约 63.5 个经度，5° 间距恰好生成 15 条经线、9 条纬线，
格距约 80–130 px —— 既不密集到遮盖底图，也不稀疏到无法定位。5 能被 10 整除，
故整十度线可用 `line.g0` 单独加粗，形成主次两级读数。

三处实现上的选择值得留意：

1. **格线覆盖「视图矩形」而非「数据 bbox」**。经线两端一律延伸到当前视图四角，
   纬线横贯左右边界；否则缩放或拖拽到边缘时会看到格线「断在画中」。
   代价是格线与度标必须随视图变化重算，故重绘挂在 `applyView()` 上。
2. **纬线 y 逐条投影求得，不可等分**。墨卡托投影下纬度间距不等 ——
   实测 15–20°N 为 82.5 px，而 50–55°N 达 129.4 px（比值 1.57），
   等分会在高纬产生可见错位。
3. **度标显式带 E / N 后缀**，避免出现「-5°E」这类自相矛盾的读数。

经纬网图层（`gGrid`）设 `pointer-events:none` 且不参与 `clipMain` 裁剪：
前者保证不拦截省份的悬停与单击，后者避免边缘度标被裁掉。

## 快速开始

成品 HTML 已在仓库中，**直接双击打开即可**，无需构建。

若要从源码重建：

```bash
# 1. 复原原始数据（原始数据体积较大，以归档形式存放，见 archive/README.md）
python -c "import zipfile; zipfile.ZipFile('archive/rawdata-2026-09-15.zip').extractall('data')"

# 2. 完整构建 + 四道门禁 + 产物一致性校验
python build/build.py
```

只校验不构建：

```bash
python build/build.py --check
```

强制重新抓取上游数据（**结果可能与本仓库成品不一致**，见 [archive/README.md](archive/README.md)）：

```bash
python build/build.py --fetch
```

**依赖**：Python 3.8+（仅标准库，无第三方包）。
`build/` 下的 JS 验证脚本需要 Node + `@playwright/test`、本机已安装 Chrome。

## 构建管线

```
fetch_national.py ─┐
fetch_cities.py   ─┼─→ data/*.json ─→ geo.py ─→ out/geo.json  ─┐
fetch_rivers.py   ─┘                                            ├─→ assemble.py ─→ 成品 HTML
                                    content.py ─→ out/data.json ─┘        ↓
                                                              校验（build.py）：数据全等 / 引用完整 /
                                                              坐标范围 / 离线自包含 / JS 语法
```

**改动上游一律走 `python build/build.py`**，不要手工按序执行单个脚本 ——
统一入口会依次运行四个阶段，并在最后执行四道门禁与产物一致性校验。

### 几何处理（`geo.py`）

1. **Douglas-Peucker 简化**：省级容差 0.008°、市级 0.018°、九段线 0.03°、河流 0.03°。
2. **面积过滤**：省级剔除面积 < 0.00015 平方度的碎片，市级为 0.0003；
   例外是三沙市（`460300`）**不做面积过滤**，以保留南海全部岛屿。
3. **整数化**：坐标 ×1000 后取整（`SCALE = 1000`），把浮点坐标压成整数，
   显著减小 JSON 体积。
4. **河段拼接**（`stitch()`）：Natural Earth 中同一条河流常被拆成多个碎段。
   按端点就近首尾相接，跨距不超过 `max_bridge = 0.45°` 时以直线补齐。
   拼接分两遍：先把碎段挂到链上，再合并端点足够近的两条链。

### 内容层（`content.py`）

- **11 个一级气象地理区划**：名称与所辖范围文字表述依据《中国气象地理区划手册》。
- **区划成员引用**：采用两种结构避免几何重复存储 ——
  `{p, all:1}` 表示整省纳入，`{p, ci:[索引]}` 表示按地级市切分纳入。
  **SPLIT 成员没有 `all` 键**，Python 中须用 `.get('all')`，JS 中可直接用 `!mem.all`。
- **`MT` 与 `SHAPES` 必须键名一一对应**（已有断言拦截），前者是注记坐标，
  后者是示意范围多边形。
- **河名标注锚点**：默认取最长河段的**累积弧长中点**；珠江、长江因弧长中点会落到
  上游山区而非河名所指河段，在 `RIVER_LABEL` 中显式锚定。

## 构建门禁

共四道，**任一失败即终止构建**。前三道在 `content.py` 末尾（数据层），
第四道在 `build.py` 的校验阶段（产物层）：

| 门禁 | 位置 | 校验内容 | 拦截的问题 |
|---|---|---|---|
| 1 | `content.py` | 每座山脉的注记点必须落在其**自身**示意范围内 | 注记悬在色块之外 |
| 2 | `content.py` | 省级要素清单中的每个要素必须与所属省范围相交 | 要素归属错配（如把怒江列给青海） |
| 3 | `content.py` | `EXTRA_RIVERS` 声称「NE 中整条缺失」必须成立 | 把 NE 中本有真实河道的河流用手工线替代 |
| 4 | `build.py` | 成品中每个 `<script>` 块必须通过 JS 语法解析 | 多余的括号导致整页空白，而构建仍报通过 |

门禁 1 有一个易踩的坑：注记点必须距多边形边界 **≥0.08°**。否则
`int(round(x * 1000))` 取整后，点可能落到边界另一侧，内外翻转。改动注记坐标后
跑一次 `build.py` 即可验证。（面积很小的山体本身余量就小，判据应看
**取整后是否仍在范围内**，而非一刀切要求 0.08°。）

门禁 3 的判据需要注意：**判断「NE 是否覆盖某河段」不能只数区间内的点数** ——
NE 中有同名碎段会让计数虚高。可靠判据是删掉手工段后，看 `stitch()` 的 chain 数
是否仍为 1。另外，河流数据文件缺失时门禁 3 会**报错而非跳过**：静默跳过会让
「未执行」与「通过」在构建日志里无法区分，门禁形同虚设。

门禁 4 的必要性在于：其余所有校验都只看**数据**，对**前端代码的语法错误完全不敏感**。
本项目曾真实发生过一次 —— 编辑降级代码时多留了一个 `})();`，产物被推送后整页空白，
而构建日志显示「全部通过」。node 不可用时该门禁会明确提示「未执行」而非静默通过。

### 产物一致性校验

`build.py` 在校验阶段会：

1. 从成品 HTML 中正则取出内嵌的 `const DATA = {...}`，与 `out/geo.json` +
   `out/data.json` **逐字段全等**比对（12 个字段）；
2. 检查前端渲染所需字段完整性，以及区划成员引用能否被解析（如
   `ci` 索引是否越界、省份代码是否存在）；
3. 检查全部注记坐标落在中国范围内；
4. 扫描成品中的 `src` / `href`，确认**零外部资源引用**（保证离线自包含）。

## 坐标系约定

**本项目混用两套坐标系，这是有意为之，不是缺陷**：

| 数据 | 坐标系 | 来源 |
|---|---|---|
| 行政区划（省 / 市 / 区 / 九段线） | **GCJ-02** | DataV.GeoAtlas（源自高德开放平台） |
| 河道中心线 | **WGS-84** | Natural Earth |

两者存在约 300–600 m 的系统性偏移。在本图比例（主图约 21 像素/经度）下约合
**0.11 像素，肉眼不可见**。但**不要在此数据基础上做高精度量测**。

## 验证与审计

### 静态审计（只读，不修改产物）

```bash
python build/audit.py         # 数据源真实性、计算逻辑与界面展示的一致性
python build/audit2.py        # 山脉中心点 / 省级要素归属 / 区划范围的三向交叉核查
python build/audit3.py        # 离线自包含性、构建链完备性、代码规模
python build/audit_issues.py  # 构建约束与数据自洽性的回归复核（只读）
```

### 渲染核查（需要 Playwright + 本机 Chrome）

```bash
export NODE_PATH="$APPDATA/npm/node_modules"   # Windows Git Bash
node build/audit_render.js 中国气象地理区划交互地图.html build/audit_shots
node build/verify_fix.js   中国气象地理区划交互地图.html build/inspect
node build/verify_tools.js 中国气象地理区划交互地图.html build/audit_shots
node build/verify_grid.js  中国气象地理区划交互地图.html build/audit_shots
```

**交付前必须确认页面的 `pageerror` 与 `console.error` 均为零。**

`verify_tools.js` 的设计要点：它**独立复算**逆投影与 Haversine（不复用页面内部状态），
否则页面算错时脚本会跟着错。覆盖三类判据：读数精度、测距与复算值一致、
以及**与既有交互的互斥性**（测距中单击不得打开省份面板、拖拽平移不得留下测点、
退出后省名与面板须恢复）。

`verify_grid.js` 同样独立复算墨卡托投影，覆盖五组判据：开关与条数、格线位置与
复算值一致（含**纬线间距随纬度递增**这一墨卡托特征，用于捕捉「误用等分」）、
度标格式、缩放平移后仍正确、以及与省份点击 / 读数 / 测距的共存性。
其中两项判据的写法值得记录，因为初版都因此失败：

- **条数期望须按「视图范围」而非「数据 bbox」计算**。格线铺满视图矩形并向外
  取整到整 `GRID_STEP`，复位视图对应 72.48–136.02°E，故是 15 条经线而非
  按 bbox（73–135.5°E）估的 13 条。
- **比较纬线间距必须取绝对值**。屏幕 y 向下增大而纬度向上增大，相邻 y 之差为
  负值，「两个负数比大小」会让判据恒不成立。

三个实测需要注意的点：

- **低对比度细线**（1.5 px 浅色虚线）必须在 `deviceScaleFactor: 2` 下截图，
  否则会误判为「未渲染」。
- 本机调用 Playwright 时用 `chromium.launch({channel:'chrome', headless:true})`
  复用系统已装的 Chrome，**无需下载 Chromium**。
- 用 `page.mouse` 做坐标类断言时，**目标点必须落在视口内**：本图比例下三亚
  对应的像素 y≈1141，超出 1100 px 高的视口，`mouse.move` 会被裁到边缘，
  读数自然对不上（这是脚本自身的问题，不是页面缺陷）。

## 已知局限与披露

本项目对声明保持较高的披露标准。以下局限**已在成品页脚的「数据来源与制图说明」
中向使用者明示**，在此汇总：

1. **区划界线为近似范围**。一级气象地理区划的原生界线以黄河、淮河、长江、南岭等
   自然地理线为界，本图按地级市（直辖市、特别行政区按区）**整体聚合**绘制。
   跨区划的地级市按主体范围归并，与文字界线存在出入（如山东泰安、淄博的实际市域
   跨越 36°N 分界线）。
2. **跨区省份的城市级归属属推断性细化**。《中国气象地理区划手册》只给出到省级与
   自然地理线级别的文字描述，**城市级切分在公开文献中并无权威版本**，本图系依据
   自然地理线所作的推断。福建、湖北两省的分市口径尤其属于推断。
3. **山脉范围为示意多边形**。山系不存在法定界线，本图按各山系的真实走向
   （NE-SW / NW-SE / E-W / N-S）与已知分布范围绘制。面积较小的名山（如泰山、黄山）
   取山体主体范围并作了约 3 倍线性放大以保证可读性，**故其范围不可用于量测**。
4. **数据缺口**：DataV 不提供台湾省的地级界线（接口返回 404），故台湾省下辖县市
   按现行区划以**点位**方式标注，无面状边界；中国澳门特别行政区 8 个堂区中有 3 个
   （花王堂区、望德堂区、风顺堂区）源数据亦未提供边界，面板中标为「无边界数据」。
5. **坐标基准混用**，见[坐标系约定](#坐标系约定)。
6. `data/ne_rivers.geojson` 原始文件占 7.3 MB 而实际仅用到其中一小部分。
   构建时由 `fetch_rivers.py` 裁剪出 `data/ne_rivers_cn.geojson`（238 个要素 / 1.19 MB，
   只保留与中国包围盒相交的整条要素、不裁剪顶点，故几何逐点不变），`geo.py` 优先读该文件。
   原始文件保留以便裁剪过程可复现。
