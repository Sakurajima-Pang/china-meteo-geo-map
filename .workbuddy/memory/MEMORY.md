# 项目长期记忆 · 中国气象地理区划交互地图

## 项目定位
单文件离线 SVG 交互地图，教学/演示用途。成品：`中国气象地理区划交互地图.html`（897.2 KB，零外部资源）。
功能：悬停/单击联动、区划框选、要素高亮、缩放平移、**经纬度读数**、**图上测距**。
**不追求"权威地图"，但所有声明必须诚实** —— 项目已有较高的披露标准，改动文案时要维持这一标准。

## 远端仓库
https://github.com/Sakurajima-Pang/china-meteo-geo-map （public，默认分支 `main`）
- **`data/` 与 `build/out/` 都不入库**。原始数据以 `archive/rawdata-2026-09-15.zip`（3.99 MB，36 文件）提供，
  克隆后解压到 `data/` 即可复现构建。详见 `archive/README.md`。
- **`.gitattributes` 声明 `* text=auto eol=lf`，不要删**：本机 `core.autocrlf=true` 会把成品 HTML
  与数据 JSON 转成 CRLF，改变产物指纹并产生虚假 diff。用 Edit 工具改 `.py` 后容易写出 CRLF，
  提交前用 `python` 检查并统一为 LF（已遇到 `content.py` 一次）。
- 交付标准：全新 clone → 解压归档 → `python build/build.py`，成品应与库中版本**逐字节相同**（零 `git diff`）。

## 三层结构
- `data/`（13 MB，不入库）：DataV.GeoAtlas 行政区划（GCJ-02，34 省 + 475 地级单元）+ Natural Earth `ne_10m_rivers_lake_centerlines`（WGS-84，7.3 MB）。
- `build/`：`fetch_national.py` → `fetch_cities.py` / `fetch_rivers.py` → `geo.py`（几何压缩，产出 `out/geo.json`）→ `content.py`（内容层，产出 `out/data.json`）→ `assemble.py`（注入 `template.html`）。
- **统一入口：`python build/build.py`**（`--check` 只校验、`--fetch` 强制重抓）。它按序调 4 个脚本并跑**四道门禁** + 产物一致性校验，**改动上游一律走它，不要手工按序跑单个脚本**。
- 门禁 1–3 在 `content.py` 末尾：① 山脉注记必须在自身示意范围内；② `FEAT` 要素必须与所属省相交；③ `EXTRA_RIVERS` 的"缺失"主张必须成立（关键词表 `_NE_KEYWORD`）。
- **门禁 4 在 `build.py` 的 `check_js_syntax()`**：成品中每个 `<script>` 块须通过 `node --check`。node 不可用时提示"未执行"而非静默通过。

## 关键约定与坑
- **成品 JS 语法必须验证**（血泪教训）：其余所有校验都只看**数据**，对**前端代码语法错误完全不敏感**。
  一个多余的 `})();` 会让整页渲染 0 个元素，而构建日志仍显示"全部通过"。**推送前必须跑渲染验证**
  （`audit_render.js`），且 `git push` 前确认 `pageerror`/`console.error` 为零。门禁 4 已能拦截此类问题。
- 坐标系**混用**：行政区划 GCJ-02、河流 WGS-84。本图比例下偏移约 0.11 px（不可见），但不要在此基础上做高精度量测。
- `mt_shapes.py` 的 `SHAPES` 与 `content.py` 的 `MT` 必须**键名一一对应**（已有断言）。**山脉范围与注记坐标的耦合易出错**：注记点须距多边形边界 ≥0.08°（面积很小的山体天然余量小，真正判据是**取整后是否仍在范围内**）。改坐标后跑 `build.py` 即可验证。
- 区划成员结构：WHOLE 成员为 `{p, all:1}`，SPLIT 成员为 `{p, ci:[索引]}`，**SPLIT 成员没有 `all` 键**。Python 处理时用 `.get('all')`，JS 里 `!mem.all` 可直接用。
- **`FEAT` 结构是 `{m:[山脉键名（无前缀）], w:[河流/湖泊（"r:"/"l:" 前缀）]}`** —— 湖泊与河流同存于 `w`。
  湖泊注记值为 `[名称, lng, lat]`，取坐标用 `[1],[2]`（不是 `[0],[1]`）。写复核脚本时极易弄错。
- 主图按"外环最大纬度 < 17.8°N 剔除"排除南海岛礁，只在附图呈现；附图包围盒 104.5–125°E / 2.5–24.5°N。
  **模板中该阈值已抽为具名常量 `MAIN_LAT_MIN`**（原硬编码 7 处），另有 `SMALL_LABEL_VERTS`（原 `p.g.length > 10`）。改制图参数请改模板顶部配置区。
- 河流拼接 `stitch()` 的 `max_bridge=0.45°`，只连链的端点，**不处理"端点接在另一链中部"**（北江/郁江即因此独立成段，视觉上仍在汇合点相接）。
- **河名标注**：`rv.lp`（数据层锚点）优先，否则按最长段的**累积弧长中点**。`RIVER_LABEL` 里为珠江、长江显式给了锚点。
- **判断"NE 是否覆盖某河段"不要只数区间内点数**——NE 有同名碎段会让计数虚高。可靠判据是删掉手工段后看 `stitch()` 的 chain 数是否仍为 1。
- NE 中的中文河英文名（易踩）：`Jialing`=嘉陵江、`Wu`=乌江（同名的 `Wujia`=乌加河）、`Min`=岷江/闽江（两条，靠 box 区分）、`Ou`=瓯江（另有云南同名）、`Fuchun`=富春江、`Bei`/`Dong`/`Xi`/`Yu`=北江/东江/西江/郁江、`Hai`+`Yongding`=海河干流+永定河。
- **NE 河流数据已裁剪**：`fetch_rivers.py` 下载后产出 `ne_rivers_cn.geojson`（7.3 MB → 1.19 MB，238 要素，
  只保留与中国包围盒 73–136.5°E/17–54.5°N 相交的整条要素、**不裁顶点**，故几何逐点不变，`geo.json` 指纹一致）。
  `geo.py` 与门禁 3 都优先读裁剪版、回退原始文件。裁剪产物已放入归档 zip。
- **`assemble.py` 要求 `template.html` 中 `/*__DATA__*/` 恰好出现 1 次**（已加断言）。若在注释里写了这个标记，
  `str.replace` 会重复注入、HTML 体积翻倍，且**产物一致性校验仍全等通过、不报警**——这个坑很隐蔽。
- **模板注释里不可出现 `script` 标签字面量**：会提前终止脚本块解析，导致语法错误。
- **GitHub 平台会剔除仓库名中的非 ASCII 字符**，中文仓库名会静默变成 `-`。仓库名只能用 ASCII。
- 本机 `git push` 若报 `schannel: failed to receive handshake` → `git config http.sslBackend openssl`。

## 前端工具：经纬网 / 经纬度显示 / 测距（2026-09-15 第六、七轮新增）
三项都建立在**逆兰勃特投影**上，实现在 `template.html`：
- **逆投影 `makeInv(bb, vw, vh, pad)`**：与 `makeProj` **共用同一组参数**故严格互逆；
  反兰勃特 `θ=atan2(px,py)` → `λ=λ₀+θ/(n·RAD)`、`φ=2[atan((F/ρ)^(1/n))−π/4]/RAD`。
  提供 `INVM(x,y)`（viewBox 坐标 → 经纬度）与 `svgPtToLL(ev)`（指针事件 → 经纬度）。
- **坐标读数取 viewBox 坐标**（复用 `svgPt()`）而非屏幕像素 —— 否则缩放后读数就错了。
- **距离用 Haversine 球面大圆**（`EARTH_R = 6371.0088`）。**不可用平面欧氏**：主图横跨 62 经度，
  实测喀什→上海 大圆 4180 km vs 平面 4229 km。`<1 km` 显示米，避免出现 "0.3 km" 这种读数。
- **基准表述**：读数是"画面反算、按 WGS-84 表述"。底图实为 GCJ-02（偏移 300–600 m），
  但**距离计算是纯数学的**、不受底图基准影响 —— 这个区别已写进页脚，改动文案时勿混。
- 精度上限：主图约 21 像素/经度 ≈ **5 km/像素**，故两个功能**仅供数量级估算**，页脚已声明。

## 投影：兰勃特等角圆锥（LCC，2026-09-15 改为气象行业惯例）
双标准纬线 **30°N/60°N**、中央经线 **105°E** → `LCC_N = 0.715567`、`LCC_F = 1.793026`。
选型依据：中国气象局与日本气象厅的中纬度天气图底图标准投影。

**改投影时必须同步的三处实现差异（最易漏）**：
1. **经线是射线、纬线是圆弧**。经线严格直线（取两点 `PM(i,-60)`/`PM(i,80)` 即可，两端远超本图范围
   以保证裁剪后贯穿画面）；纬线是同心圆弧，**最大弓高 171 px，不可直线近似**，须按经度
   （`step = GRID_STEP/8`）采样成点串后逐段 `clipLineToRect` 拼接。
2. **`projBounds()` 不能用四角取极值** —— 纬线下凹，y 极值落在南边界中央而非角点。
   改为沿四条边界密集采样（N=200，与 N=2000 差 < 0.001 px）。
3. **经纬网范围取自 `MAIN_BB` 而非视图四角** —— 视图四角在扇形内容之外，反算经度可达 50°E/155°E，
   会画出 22 条无用经线且度标全部落在画面外。改用数据包围盒后为 **15 条**。

**两个已踩的坑**：
- **南北倒置（真实 bug）**：`lcc` 曾误取 `y=−ρ·cosθ`，叠加 makeProj 的「投影 y↑ → 屏幕 y↑」后整图翻转。
  正确为 `y=+ρ·cosθ`（北在上），`makeInv` 同步用 `atan2(px, py)`。
- **度标夹取基准**：必须夹到**画面边界**（`vx0+12`/`vx1-12`/`vy0+10`/`vy1-6`），
  **不能夹到内容 bbox**。内容 bbox 取的是省界几何极值，在 17.6°N 一带真实省界只到 108–110°E（海南岛），
  而格线沿 `MAIN_BB` 的 73–135.5°E 铺开 —— 两者不同源。夹到内容边界会把东西各 5 个度标挤到同一竖线叠压。
  实测不夹取时 24 个度标本就全在画面内。

## 下辖单元命中区域：`.cty` 必须 `fill:transparent`，不可 `fill:none`
SVG 中 `fill:none` 会让**面**不参与命中测试，只剩描边可点。典型受害者是**青海海西州**：
面积大但形状稀疏，其外接盒内 100 点均匀采样**仅 4 点**落在真实辖区内，且外接盒中心点命中的是省界。
用户感受就是"点在州内却毫无反应"。正确写法 `fill:transparent;pointer-events:visiblePainted;fill-rule:evenodd`。
- **`fill-rule:evenodd` 不可省**：海西州被玉树州地理分隔成东西两块（数据层即 `polys=2`，多外环），
  `evenodd` 才能让相邻单元正确成洞。
- **"海西被玉树切成两半"是该州的正常形态**，数据与渲染均如实体现，不是数据缺口。
  此前"看不见"实为面板内容超出可视高度（`scrollHeight 1496` vs `clientHeight 1012`），
  海西州位于折叠线以下，需在面板内滚动。
- ⚠ **CSS `.cty` 规则是跨行声明的**，且**注释正文里就写着 `fill:transparent` 与 `fill:none`**。
  故任何针对该规则的检查必须：① 先合并整条规则（跨行）；② **先剥掉 `/* */` 注释再判**。
  否则「改回 fill:none」这个真实缺陷不会被检出（实测确认是空检查）。
- ⚠ 规则内**不要保留冗余的 `fill:none` 前置声明**。虽被后面的 `fill:transparent` 覆盖（CSS 后者胜），
  但语义与注释完全相反 —— 日后误删 `fill:transparent` 那行即静默退回不可点击状态。


### 交互互斥的三个坑（都是实测踩出来的，勿重蹈）
1. **不要用 `stopPropagation` 做互斥**。测距中单击省份不该开面板，需在省份/城市处理器里查询 `measOn` 让路。
   曾试图在 svg 的**捕获阶段** `stopPropagation` —— 结果把**同一 svg 冒泡阶段的 pointerup 取点监听一并掐掉**，
   测距彻底失效（事件追踪只见 `svg-cap pointerup`、无 `svg-bub pointerup`）。
2. **双击结束用浏览器原生 `dblclick` 事件**，不要自造"两次 pointerup 间隔 < N ms"判据 ——
   自造阈值会把使用者连续快速取点误判成结束（实测 3 个点都落不下去）。dblclick 之前的两次 pointerup
   会多留点，`clearMeas()` 一并丢弃即可。
3. **`labelsBak`（省名备份）的还原语句必须置于 `setMeasure` 最前**。该函数可被重复调用
   （按钮/Esc/双击），若"备份"写在"还原"之前，第二次进入会用已置 `false` 的值覆盖备份，退出后省名再也回不来。

### 其他实现约定
- 测距折线图层 `gMeas` **不参与 `clipMain` 裁剪**（否则缩放时线段越出画面会"闪烁消失"）。
- 「折线 + 橡皮筋」分离：分段折线与里程标注只在落点/缩放时重建；指向指针的虚线单列一条高频更新。
- 坐标读数与测距面板分别固定在 svgbox 的**左上**与**右上**（贴右下会压住南海诸岛附图）；
  `moveTip()` 查询 `coordOn` 以避开读数框的遮挡。

### 经纬网（`gGrid`，2026-09-15 第七轮 · 兰勃特版已改）
`GRID_STEP = 5`（主图横跨 62.5 经度 → 兰勃特下格距南宽北窄，约 45–130 px）；整十度线用 `line.g0` 加粗成两级。
- **格线范围取自 `MAIN_BB`**（**不是**视图四角，也**不是**内容 bbox）：取其 73–135.5°E / 17.6–53.8°N
  向外 `floor/ceil` 到整 5° → **15 条经线**（按 bbox 73–135.5 直接估会算成 13 条，错）。
  裁剪框取「视图矩形 ∪ 数据范围」：复位时即数据范围，放大到局部时以视图为准。
- **纬线是按弧线采样，不可等分也不可直线化**：兰勃特下纬线是圆弧，最大弓高 171 px。
- **`gGrid` 的双重豁免**：① 必须 `pointer-events:none`，否则拦截省份点击；
  ② 必须**不参与 `clipMain`**，否则边缘度标被裁掉。二者已固化为审计项。
- `drawGrid()` **必须先清空再重绘**（`while(gGrid.firstChild) gGrid.removeChild(...)`）：
  它在按钮切换与每次 `applyView` 都会被调用，少了清空就会叠加格线（已固化为审计项）。
- 度标显式带 `E`/`N` 后缀，避免出现「-5°E」这类自相矛盾的读数。

## 验证原则：判据必须逐条注入真实缺陷确认能失败（否则是空检查）
**一个恒通过的检查毫无价值，且比没有检查更危险** —— 它会让人误以为有防护。
本项目已多次逮到空检查，累计至少 7 处，全是"看起来对、实际测不出东西"：
- `pointer-events` 检查写成两个独立的全文件子串测试 → 删掉 gGrid 自己的属性后仍通过（别的图层也用了该值）。
- `gGrid` 的 id 与属性分离测试 → 同上。
- 「南北倒置」检查写成 `'rho*Math.cos(th)' in body` → 改成 `-rho*Math.cos(th)` 后子串**依然存在**。
  即**曾真实发生过的那个 bug 不会被检出**。
- 「格线取自 MAIN_BB」只判函数体含 `MAIN_BB.lng[0]` → 函数体后段算裁剪框时仍引用它，改 `lngMin/lngMax` 后仍通过。
- 「度标夹取」只判含 `vx0 + 12` → 被同函数内 `lx2` 那行满足。
- `.cty` 的 `fill:transparent` 检查未剥 CSS 注释 → 注释正文里就写着该串，改回 `fill:none` 仍通过。

**固化的做法**：
1. 判据尽量**绑定到具体声明语句**（整行匹配），不要只判"函数体含某子串"。
2. 遇到"含某标识符"的检查，先想**同一函数里还有没有别处也引用它**。
3. 文本检查前先**剥掉注释与空白**，注释里常复述被检查的关键字。
4. 写完判据就跑一次**注入回归**：`build/dev-scratch/inject_proj.py`（对投影/经纬网/命中区注入真实缺陷）。
   它曾一次揪出 4 条空检查。**注入必须是真实且有效的缺陷**（语义等价的小改不算，那不是空检查而是注入无效），
   且注入后要断言补丁确实进入了被检文本，否则"未检出"可能只是补丁写错了位置。
5. 容差不可设到机器精度：经线端点经度由 `toFixed(1)` 落格，在斜线上反算会放大误差，
   实测最大偏差 0.0090°；按 1e-6 设容差会**恒失败** —— 那不是页面缺陷，是该判据不可实现。
   此时应放宽容差并**另加**一条更直接的判据（如"端点横向偏移 < 1 px"）。

## ⚠ 事故教训：未提交的工作绝不能用 `git checkout` 回退
2026-09-15 曾在验证注入补丁时，用 `git checkout build/template.html` 恢复模板 ——
但当时兰勃特改造**从未提交**，git 直接回退到墨卡托版，整个改造被摧毁（`grep -c LCC_N` → 0）。

**恢复路径（三步，前两步失败，记录下来以便复用）**：
1. `changes-detail` 的 unified diff 重放 → **失败**。hunk 只带 8 行上下文，顺序搜索锚错位置；
   且 `oldStart` 与已提交文件不符（diff 基线更古老），19 个 hunk 全部无法定位。
2. 改用 `oldStart` 精确行号定位 → **仍全失败**（`oldStart` 指新侧累积行号，非旧侧）。
3. **成功**：`~/.workbuddy/workspace/sessions/<sid>/modify_backup/` 下留有
   `10.m.<hash>.<文件名>` 快照，含完整改动后的文件。**反向解构 `assemble.py` 的数据注入**
   （把 `<script>const DATA = {...};</script>` 还原为 `<script>const DATA = /*__DATA__*/;</script>`）
   即可从成品 HTML 反推回 `template.html`。

**要点**：`changes-detail` 目录内容会**自动轮转**（数十分钟内即被替换），发现后须**立即** `cp` 到项目内。
**正确做法**：改动前先提交，或先备份到项目内再动 git；注入工具的清理**不要用 git 恢复**。

### 空检查陷阱（必须遵守）
**"检查通过"不等于"检查有效"。** 新增判据后，必须**逐条注入真实缺陷**验证它会失败，否则可能是空检查。
已累计发现 **3 类**空检查（每类都是实测复现的）：
- 「页脚披露」从**成品 HTML** 取页脚，而注入只改 `template.html` → 读的是旧成品。**改为从模板取**。
  推而广之：**凡检查模板内容，就不要从成品读**（成品是 assemble 的产物，不同步）。
- 「省名备份顺序」对**全文件**取 `index` 比较，而两处关键字在全文件里的相对位置与函数内先后顺序不是一回事
  → **限定在 `setMeasure` 函数体内**比较。
- 「`gGrid` 设 `pointer-events:none`」写成 `'"pointer-events":"none"' in tmpl and 'id:"gGrid"' in tmpl`
  —— **两个独立的全文件子串测试**。实测删掉 gGrid 自己的该属性后**依然通过**（别的图层也用了这个值）。
  → **多条件判据必须把各条件绑到同一个语义单元上**（此处：绑定到含 `id:"gGrid"` 的那一行），
  不可拆成互不相关的全局 `in` 测试。
- **注入锚点必须逐字核对**（含空格）。本轮一条注入因锚点少写一个空格（`gGrid  = ` 有两个空格）而**静默跳过**，
  被误当成"未检出"；另有一条注入的 old/new 写成同一字符串（等于没改），得出的是假结论。
  → 注入前先 `assert old in src`，且 **old != new**。

## 验证方法（复用）
- `NODE_PATH="$APPDATA/npm/node_modules" <node> xxx.js` + `chromium.launch({channel:'chrome',headless:true})`，用全局 `@playwright/test`，无需下载 Chromium。
- **`audit_render.js` 需要两个参数**：`node build/audit_render.js <HTML路径> <输出目录>`，缺参数会报 `ERR_INVALID_ARG_TYPE`。
- **`verify_tools.js`**（新增）：验证经纬度读数与测距，**独立复算**逆兰勃特投影与 Haversine（不复用页面内部状态，
  否则页面算错脚本会跟着错），30 项检查，同样需两个参数。
- **`verify_grid.js`**（新增）：验证经纬网，**独立复算**兰勃特投影，26 项检查，同样需两个参数。
  初版**三处判据全错，且都是脚本自身的问题**（不是页面缺陷），值得记住：
  ① **条数期望要按「视图范围」算**，不能按数据 bbox 估 —— 格线是铺满视图矩形并向外取整的，
     复位视图对应 72.48–136.02°E 故是 15 条，按 bbox 73–135.5°E 会估成 13 条；
  ② **比较纬线间距必须取 `Math.abs`** —— 屏幕 y 向下增大而纬度向上增大，相邻 y 之差为负，
     "两个负数比大小"会让判据恒不成立；
  ③ **点击类断言不能硬编码屏幕坐标** —— 随手取的点可能落在海上，`elementFromPoint` 返回 `#map`，
     该点本就点不出面板，检查会恒失败。改为**按命中测试动态找省内点**，并加一条
     「同一采样点在关闭网格时同样命中省份」作对照，才能证明是网格没干扰。
- 交付前必须确认页面 `pageerror` / `console.error` 均为零。
- **推送前必做**：渲染验证 + 全新 clone 端到端验证（解压归档 → 构建 → `git diff` 为空）。
- 低对比度细线（1.5 px 浅色虚线）必须在 `deviceScaleFactor:2` 下截图，否则会误判"未渲染"。
- 构造"损坏样本"测降级路径时，直接删字段极易留下语法错误；可靠做法是**从成品中抽取目标逻辑**，
  拼一个最小测试页验证，而不是改整份 HTML。
- **临时 JS 脚本不要放 `/tmp`**：Git Bash 下会被 node 解析成 `D:\tmp\x.js` 而报 MODULE_NOT_FOUND。
  放到 `build/dev-scratch/`（已在 `.gitignore` 中）跑完即删。
- **用 `page.mouse` 做坐标类断言时，目标点必须落在视口内**：本图比例下三亚映射到 y≈1141 px，
  超出 1100 px 高的视口，`mouse.move` 会被裁到边缘，读数自然对不上（是脚本的 bug，不是页面的）。
- **面板类断言不要用"文本有变化"**，要用"是否仍为初始占位文案"——前一测试可能已改过标题，比较变化会漏判。
